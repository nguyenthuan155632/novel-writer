# Chapter Deletion Design

**Date:** 2026-05-01  
**Status:** Approved  
**Approach:** Hard Delete with DB Cascades + Manual Cleanup (Approach A)

## 1. Goal

Enable deletion of a chapter and all its dependent data/relationships, with the constraint that **only the latest chapter in a story may be deleted**.

## 2. Context

The project is a monorepo with:
- `@novel/db` — Drizzle ORM + PostgreSQL
- `apps/api` — Fastify REST API
- `apps/web` — Next.js frontend
- `apps/worker` — BullMQ job worker

The `chapters` table has many dependent tables with `onDelete: 'cascade'` FKs. However, three tables reference chapters by `chapterNumber` (integer) without FK constraints and require explicit cleanup.

## 3. API Endpoint

```
DELETE /api/stories/:storyId/chapters/:chapterNumber
```

## 4. Validation

1. Verify the chapter exists for the given `storyId`. If not found → **404 Not Found**.
2. Check `chapter.status === 'generating'`. If true → **409 Conflict** (prevents race with active worker).
3. Query `MAX(chapterNumber)` for the story. If `requestedChapterNumber < max` → **400 Bad Request** with message: *"Only the latest chapter can be deleted."*

## 5. Deletion Sequence

All steps execute inside a single Drizzle transaction.

| Step | Operation | Table(s) |
|------|-----------|----------|
| 1 | `DELETE` | `timeline_events` WHERE `story_id = ? AND chapter_number = ?` |
| 2 | `UPDATE` | `open_threads` SET `opened_chapter = NULL` WHERE `opened_chapter = ? AND story_id = ?` |
| 3 | `UPDATE` | `open_threads` SET `planned_resolution_chapter = NULL` WHERE `planned_resolution_chapter = ? AND story_id = ?` |
| 4 | `DELETE` | `canon_facts` WHERE `source_chapter = ? AND story_id = ?` |
| 5 | `DELETE` | `chapters` WHERE `id = ?` |

Step 5 triggers database cascades that automatically delete rows from:
- `chapter_packets`
- `chapter_summaries`
- `context_packets`
- `pending_canon_updates`
- `validations`
- `llm_calls`
- `high_stakes_reviews`

## 6. HTTP Responses

| Status | Condition |
|--------|-----------|
| `204 No Content` | Deletion succeeded |
| `400 Bad Request` | Chapter is not the latest in the story |
| `404 Not Found` | Chapter does not exist for the story |
| `409 Conflict` | Chapter is currently being generated by the worker |

## 7. Edge Cases

- **Story has only one chapter**: Deletion is valid (it is the latest). After deletion, the story has zero chapters.
- **Concurrent delete requests**: Row-level locking during the transaction serializes safely.
- **Partial failure**: The transaction guarantees atomicity — all deletions succeed or none do.

## 9. Testing Considerations

- Unit test: delete latest chapter succeeds and cleans up all dependents.
- Unit test: delete non-latest chapter returns 400.
- Unit test: delete generating chapter returns 409.
- Unit test: delete nonexistent chapter returns 404.
- Verify `open_threads` columns are nulled, not deleted.
- Verify cascade-covered tables are cleaned automatically.

## 10. Future Considerations (out of scope)

- Soft delete / trash / recovery mechanism (not needed now).
- Bulk chapter deletion (not needed now).
- Renumbering remaining chapters (explicitly avoided by "latest only" constraint).
